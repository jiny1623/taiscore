# Data Format

TAIScore evaluates critique-guided revision transitions:

```text
(prompt, initial_response, critique, revised_response)
```

During critic training, the critic produces `critique`; the refiner endpoint produces `revised_response`; the judge endpoint scores the full transition.

## Reward Inputs

`compute_score_batched` expects the following fields:

```python
scores = compute_score_batched(
    data_sources=["writing"] * batch_size,
    solution_strs=critiques,
    ground_truths=[None] * batch_size,
    extra_infos=[
        {
            "user_prompt": prompt,
            "draft_y0": initial_response,
            "example_id": group_id,
        }
    ],
)
```

Fields:

- `solution_strs[i]`: critique generated by the critic.
- `extra_infos[i]["user_prompt"]`: original user instruction.
- `extra_infos[i]["draft_y0"]`: initial actor response before critique.
- `extra_infos[i]["example_id"]`: group identifier used for within-prompt GRPO normalization.

Rollouts with the same `example_id` are normalized together. If an `example_id` is missing, the implementation treats the row as a singleton group.

## JSONL Example

A public dataset can be represented as JSONL before conversion to a trainer-specific format:

```json
{"id": "example-0001", "prompt": "Write a short story about...", "draft_y0": "Initial response text..."}
{"id": "example-0002", "prompt": "Explain the tradeoffs of...", "draft_y0": "Initial response text..."}
```

Trainer adapters should map these fields into the `extra_infos` contract above.

## Preference Pair Format

For actor DPO training, refinement pairs are commonly stored as:

```json
{"prompt": "User instruction...", "chosen": "Revised response...", "rejected": "Initial response..."}
```

The exact filtering policy is experiment-specific. This repository only defines the reward-side data contract.
